02 · modelo mental

Captain converses, consults knowledge, and proposes only configured actions.

Message
→
Assistant + rules
→
Scenario
if it matches
→
Response, tool, or handoff

Correct design

  • Knowledge reviewed before automation.
  • Small tools with explicit purpose.
  • Handoff when data, permission, or certainty is missing.

Don’t assume

  • That a tool authorizes an action by itself.
  • That the assistant can invent an integration.
  • That scenarios resolve ambiguity via persisted priority.

03 · antes de configurar

Enable the capability and prepare a human support path.

Account and permissions

  • Captain and the provider/model must be available for the account.
  • For external MCP, enable captain_mcp.
  • Creating/editing assistants, scenarios, Custom Tools, and MCP requires an administrator.
  • Agents can query the assistant and use Playground without managing those configurations.

Operations

  • Define objective, content owner, and escalation criteria.
  • Prepare the pilot inbox, but do not assign the assistant yet.
  • Ask the instance admin to confirm the account mode disabled for auto-resolve.
  • Prepare normal, edge, and handoff cases to test.
⚠Bot exclusivity: Captain does not respond or schedule automatic resolutions in inboxes with Agent Bot or Dialogflow active.

05 · configuración completa

An assistant starts with a concrete identity, not a list of tools.

Safe example of Assistant Basic Settings

NameAcme Support
Product nameAcme Cloud
DescriptionHandles basic usage and published plans; does not confirm refunds or commercial exceptions.

Features: enable based on evidence

Conversation FAQs✓ if the team will review suggestions.
Memories✕ at first, until a usage policy is defined.
Citations✓ only with reviewed public sources.
Contact attributes✕ unless required and approved attributes are needed.

Also available: ignore WhatsApp groups and concrete targets/identifiers; use them to reduce scope, never to hide a configuration failure.

06 · configuración operativa

Complete the scope and messages before assigning the first inbox.

Scope example

Ignore groups✓ if the pilot will not handle WhatsApp groups.
Ignored targetsOnly real numbers or identifiers that must be excluded; empty in this pilot.
Legacy instructionsNot applicable in V2: use guidelines, guardrails, and scenarios.

Messages sugeridos

Handoff message“I’ll hand the conversation over so a person can continue with you.”
Resolution message“It looks like your request has been resolved. You can contact us again if you need help.”
!The handoff message must not promise a team, owner, or response time. The resolution message is only used when auto-resolve behavior is enabled.

07 · contexto y alcance

Reliable knowledge comes before action.

FAQs

Approve only reusable responses; review suggestions before publishing.

Documents

Public URL or relevant PDF. A PDF has a maximum size of 10 MB and is processed/indexed.

Inboxes

Select a pilot channel with no conflicting bots and assign it only after Playground.

🔎Citations: use public URLs suitable for the client. Do not cite URLs with credentials, signed parameters, PDFs, or private destinations.

08 · comportamiento seguro

Separate style, prohibitions, and automatic resolution.

Response guidelines

How to respond: language, tone, structure, clarification questions, and when to offer human help.

“Respond in English, in short steps.”

Guardrails

What not to do: promises, sensitive PII, regulated decisions, or actions without confirmation.

“Do not request or repeat card details.”

Disabled

No automatic resolution. Recommended for launch.

Evaluated

With captain_tasks: resolve if complete; hand off if incomplete.

Legacy

Close after inactivity; use only if the team knows that behavior.

Account configuration: there is no selector in the current Captain UI. The instance administrator must verify captain_auto_resolve_mode; without an explicit value, the fallback depends on captain_tasks.

09 · especializar sin solapar

A scenario is a specialized agent for a precise intent.

Visible fields

  1. Title: the intent, not the solution.
  2. Description: entry signals and exclusions.
  3. Instruction: short and verifiable steps.
  4. Tool links: are inserted from the selector inside the editor.

Real activation

A new scenario is created enabled by default and the current UI does not provide a toggle.

There is no persisted priority: make scenarios mutually exclusive and configure them before assigning the inbox.

✓There is no separate Tools field in the UI: the system infers tools from tool:// links in the instruction and rejects unconfigured references.

10 · primer caso copiable

Exact fields

TitleBusiness hours
DescriptionQuestions about hours, channels, and coverage; does not manage cases.
InstructionExample text without inserting tool:// links.

Al crear: is enabled. Do this before assigning the pilot inbox.

Instruction
Si la persona pregunta por horarios, canales o cobertura:
1. Responde solo con conocimiento aprobado.
2. No ejecutes acciones ni prometas seguimiento.
3. Si el pedido está fuera de este alcance,

✓Expected outcome: there is no tool chain. The scenario gives a limited response and the main assistant resumes out-of-scope intentions.

12 · integración por cuenta

Define a small, safe, and verifiable contract before using it in a scenario.

Fictional Custom Tool

Title / IDCheck order status · custom_consultar_estado_pedido expected without collision.
DescriptionQuery the published status of an order by order_id; read-only.
HTTP methodGET
Endpoint URLhttps://api.ejemplo.test/v1/orders/{{ order_id }}
AuthBearer · valor ficticio demo-no-usar
Parameterorder_id · string · required · identificador público.

Minimal response to the model

Response template
Status: {{ response.status }}
Estimated date: {{ response.estimated_date }}
# Do not return address, phone, or payment data.

Test: is disabled because the URL contains {{ ... }}.

Privacy: each call adds account/assistant headers and, if present, conversation, contact, email, and phone. Authorize the endpoint as a receiver of personal data.

⚠Keep ideally 10 or fewer to make selection easier; the maximum is 15 per account. Persistence requires public HTTPS; no localhost, IP, .local, or the app itself. Store secrets only in Auth and use the ID inserted by the selector. A mutation requires its own confirmation.

13 · integración por assistant

Connect, discover, and filter the tools of the remote server before assigning it.

Create fictional MCP server

NameInventory Demo
DescriptionCheck product availability; read-only.
URLhttps://mcp.ejemplo.test/mcp
Transport / RPCstreamable_http · Empty RPC endpoint.
Auth typeBearer · fictional token
Enabled✓

Attach to the assistant

  1. Selecciona Inventory Demo.
  2. After Connect, choose only stock_lookup.
  3. Expected ID without collision: mcp_inventario_demo_stock_lookup.
  4. Insert the tool from the scenario selector; do not write the memory ID.
  5. Server + association enabled and state connected.

↻Import Configuration accepts remote JSON and rejects stdio. For immediate changes, use Connect/Refresh; the job checks every 10 minutes and effective renewal may take about 20 minutes more in queue.

14 · construir de afuera hacia adentro

The configuration order determines which tools the scenario can use.

1Create/enable custom_consultar_estado_pedido with read-only permissions.Cuenta
2Conectar Inventory Demo, adjuntarlo al assistant y filtrar stock_lookup.Assistant
3Verify that the required built-ins are configured and available.Catálogo
4Create the scenario —it remains enabled—, test it, and only then assign the inbox.Escenario

Allowed

Order status, stock, private note, priority, and handoff: all defined with concrete identifiers.

Blocked / fallback

If order_id is missing, a tool fails, or the delay is not confirmed: do not mutate; ask for the data or offer a handoff and execute it only if accepted.

15 · escenario copiable

Order with possible delay: query, record, and escalate conditionally.

Title: Order with possible delay
Description: Check status and stock when an order may be delayed.

Instruction
If a person asks about an order with possible delay:
1. Ask for order_id if missing. If it is not provided, go to the fallback in step 7.
2. Use [Check status](tool://custom_consultar_estado_pedido).
   If it fails or does not confirm the status, go to the fallback in step 7.
3. Only if the status requires replenishment, use
   [Check stock](tool://mcp_inventario_demo_stock_lookup).
   If it is unavailable or fails, go to the fallback in step 7.
4. Only with confirmed delay, record the result with
   [Add private note](tool://add_private_note).
5. Only if the delay is confirmed, use
   [Update priority](tool://update_priority) to high.
6. Explain only confirmed results.
7. Fallback: offer human help. If accepted, use
   [Transfer to a human](tool://handoff); if not, end without more tools.
8. If the intent is not an order, return to the main assistant.

Nota: the IDs are the expected ones in a demo account without collisions. Insert each reference from the editor selector. The runtime supports up to 128 tools; a scenario allows assigning up to 127.

16 · cómo demostrarlo

The trace shows that configuration does not replace authorization.

✓Two tests: Playground shows routing and traces, but it does not have a real conversation; private note, priority, and human handoff are validated in the pilot inbox. In V2 there is no direct @ selector in Playground.

17 · two different directions

Distinguish who consumes MCP and which authentication applies.

Captain consumes external MCP

A remote HTTP(S) server is configured with auth none/Bearer/API key, connected, and tools are filtered by assistant.

Ejemplo: Inventory Demo

AI client consumes native MCP

A client connects to the account endpoint /mcp/:account_id/:slug with OAuth or an API access token and the allowed catalog.

Does not publish import/export

🔐A Captain run toward native MCP includes a signed, one-time proof tied to the account, assistant, server, endpoint, tool, and arguments. Minimal privilege is still necessary.

18 · demostración local

Choose an example message and verify the decision before the real Playground.

Dynamic: read the output, ask the group to identify what is allowed, and then reproduce the same case in Playground.

19 · validate before exposing

Playground validates decisions; the pilot inbox validates the operational context.

In Playground

  1. Question covered by FAQ/document.
  2. Simple scenario without tools.
  3. Routing of the complex case and external tools.
  4. Missing data and disconnected tool.
  5. Tool traces and handoffs between agents in V2.

In the pilot inbox

  1. Account mode disabled confirmed.
  2. Now assign a channel, schedule, and owner.
  3. Validate notes, priority, and human handoff.
  4. Measure reopenings and unresolved queries.
  5. Scale only with stable evidence.
◌Playground uses the real configuration, but it does not create a conversation: tools tied to the conversation do not produce their final effects there. Validate them in the pilot inbox.

20 · diagnose without guessing

Fix the configuration that limits the flow; do not add instructions to hide the problem.

Custom Tool test disabled

Cause: URL with {{ ... }} or request template.

Action: with POST/PUT/PATCH, first clear the Request template; then use a safe static GET URL, or create a temporary tool. The test runs a real call.

MCP tool does not appear

Cause: server disconnected/disabled or tool not selected in the association.

Action: Connect/Refresh, verify state connected, enabled, and include/exclude filter.

Wrong scenario

Cause: overlapping descriptions or signals.

Action: narrow the intent and add exclusions; there is no persisted priority to fix it.

Insecure endpoint or network error

Cause: Unsafe HTTP for Custom Tool, private/local host, or DNS to private IP.

Action: use public HTTPS and review timeout/response; do not try to bypass SSRF protections.

21 · operate with evidence

The first launch is a controlled experiment, not the end of the design.

Overview

Handled, automatic resolution, handoffs, reopenings, coverage, and estimated time saved.

Generation details

Inspect scenarios, tools, and Captain response/note sources to audit decisions.

Weekly routine

Correct FAQs, remove useless tools, review errors, and repeat the same Playground cases.

  • Assistant, sources, and pilot inbox reviewed.
  • No Agent Bot/Dialogflow in the inbox.
  • Guidelines, guardrails, and auto-resolve defined.
  • Scenarios no solapados; salida segura clara.
  • Custom/MCP with minimum privilege and no real secrets.
  • Maximum 128 in runtime, 127 per scenario, and 15 Custom Tools.
  • Normal, edge, and handoff cases approved.
  • Owner, monitoring, and rollback defined.

Closing

Start narrow.
Measure. Learn.
Scale carefully.

Captain works best with reliable knowledge, explicit decisions, and small-scope tools.
